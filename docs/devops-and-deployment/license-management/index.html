Offline RSA-4096 License Management & On-Premise Deployment

PrismScale utilizes an Asymmetric Offline Digital Licensing System (RSA-4096 with SHA-512) designed specifically for high-security, air-gapped, and strictly regulated enterprise environments (Banking, Defense, Healthcare, Public Sector).

Unlike legacy SaaS software that requires periodic "phone-home" telemetry pings to validate entitlement, PrismScale verifies licenses 100% locally and offline inside your private infrastructure.

1. Architectural Philosophy: Zero Phone-Home​

In accordance with Guardrail 5 (Offline Asymmetric Licensing) and Guardrail 1 (Zero-Trust Data Plane):

  • No External Outbound Connectivity: The PrismScale Control Plane and Data Plane agents do not initiate outbound HTTP/HTTPS calls to PrismScale licensing servers.
  • Air-Gapped Operation: The platform operates flawlessly in classified networks, isolated VPCs, and networks protected by unidirectional data diodes.
  • Cryptographic Trust Anchor: Entitlements, valid dates, monitored service quotas, and enabled modules are digitally signed using PrismScale's 4096-bit master private key. The backend validates this signature using the embedded public key on boot and during periodic in-memory checks.

2. On-Premise vs SaaS: The "No Customer ID" Principle​

A common question from enterprise DevOps teams is:

"What Customer ID do we need to configure before deploying PrismScale On-Premise?"

Answer: You do not need to generate, know, or configure any Customer ID.

DimensionOn-Premise / Air-Gapped DeploymentMulti-Tenant Cloud SaaS
Customer ID SetupZero-touch. Generated automatically into the signed file (e.g. banca-transilvania-4a8f9c12).Bound to the tenant UUID in the cloud database.
Network Egress0 bytes. Completely disconnected.Standard TLS API egress to cloud backend.
Activation MethodFile mount (prismscale.lic) or Secret injection.Assigned via SuperAdmin portal or license key.
Audit IdentityExtracted from the verified cryptographic payload.Resolved from JWT tenant claim.

The customer never needs to type or match IDs. The Control Plane self-extracts its identity and permissions directly from the verified cryptographic payload.

3. Anatomy of the License File (prismscale.lic)​

The license file (prismscale.lic) is a signed JSON document containing the operational contract and its asymmetric digital signature:

{
  "customerId": "banca-comerciala-meridian-4a8f9c12",
  "customerName": "Banca Comercială Meridian S.A.",
  "issuedAt": "2026-09-16T12:00:00Z",
  "validUntil": "2027-09-16T12:00:00Z",
  "maxMonitoredServices": 25,
  "enabledModules": [
    "EU_AI_ACT_CLASSIFICATION",
    "CAB_GOVERNANCE",
    "RUNTIME_FIREWALL_PRO",
    "DORA_NIS2",
    "ANNEX_IV_TECHNICAL_FILE"
  ],
  "signatureAlgorithm": "SHA512withRSA-4096",
  "signature": "W5yqN8Z2kL7mP...[512 bytes Base64-encoded RSA-4096 signature]...9xT=="
}

Cryptographic Tamper-Proofing​

If any byte in the envelope is modified (for example, extending "validUntil" or increasing "maxMonitoredServices"), the cryptographic signature verification fails immediately with INVALID_SIGNATURE, and the application refuses to unlock the modified capabilities.

4. Deployment & Activation Methods​

PrismScale provides four flexible methods to inject the license into the Control Plane container:

Method 1: Docker Compose (Recommended for Pilots & Single VM Deployments)​

Place the prismscale.lic file in your deployment directory alongside your docker-compose.yml:

version: '3.8'

services:
  prismscale-backend:
    image: ghcr.io/prismscale/control-plane-backend:latest
    container_name: prismscale-backend
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - PRISMSCALE_LICENSE_FILE=/app/license/prismscale.lic
      - SPRING_DATASOURCE_URL=jdbc:postgresql://postgres:5432/prismscale
      - SPRING_DATASOURCE_USERNAME=prismscale_user
      - SPRING_DATASOURCE_PASSWORD=StrongSecurePassword123!
    volumes:
      # Mount the license file as read-only
      - ./prismscale.lic:/app/license/prismscale.lic:ro
    depends_on:
      - postgres

  prismscale-frontend:
    image: ghcr.io/prismscale/control-plane-frontend:latest
    container_name: prismscale-frontend
    ports:
      - "80:80"
    depends_on:
      - prismscale-backend

  postgres:
    image: postgres:16-alpine
    container_name: prismscale-postgres
    environment:
      POSTGRES_DB: prismscale
      POSTGRES_USER: prismscale_user
      POSTGRES_PASSWORD: StrongSecurePassword123!
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:

Launch the stack:

docker compose up -d

Method 2: Kubernetes & Helm (Enterprise High Availability)​

In Kubernetes, inject the license as a native Secret:

1. Create the Kubernetes Secret​

kubectl create secret generic prismscale-license \
  --from-file=prismscale.lic=/secure/path/to/prismscale.lic \
  -n prismscale

2. Configure Helm values-production.yaml​

backend:
  replicaCount: 3
  license:
    existingSecret: "prismscale-license"
    licenseKeyPath: "prismscale.lic"
    mountPath: "/app/license"

3. Deploy or Upgrade​

helm upgrade --install prismscale ./prismscale-helm-chart.tgz \
  --namespace prismscale \
  --values values-production.yaml

Method 3: Environment Variable / Secrets Manager (Vault, AWS Secrets, Azure KV)​

If your enterprise security policy prohibits mounting files to container filesystems, you can inject the entire JSON content directly into the PRISMSCALE_LICENSE_KEY environment variable:

export PRISMSCALE_LICENSE_KEY='{"customerId":"banca-transilvania-4a8f9c12","customerName":"Banca Transilvania S.A.","validUntil":"2027-09-16T12:00:00Z","maxMonitoredServices":50,"enabledModules":["EU_AI_ACT_CLASSIFICATION","CAB_GOVERNANCE","RUNTIME_FIREWALL_PRO"],"signatureAlgorithm":"SHA512withRSA-4096","signature":"..."}'

The backend automatically detects the inline JSON string, decodes it, and validates the signature in-memory.

Method 4: Bare-Metal JAR / Systemd Service​

For direct JVM deployments on dedicated Linux servers:

# Place the license in standard configuration directory
sudo mkdir -p /etc/prismscale/
sudo cp prismscale.lic /etc/prismscale/prismscale.lic
sudo chmod 400 /etc/prismscale/prismscale.lic
sudo chown prismscale:prismscale /etc/prismscale/prismscale.lic

# Launch the JVM with license path argument
java -Dprismscale.license.file=/etc/prismscale/prismscale.lic \
     -jar /opt/prismscale/prismscale-backend.jar

5. License Lifecycle, Quotas & Grace Period State Machine​

PrismScale implements a non-disruptive, fail-safe lifecycle model ensuring production stability:

┌─────────────────┐       30 days before       ┌────────────────────────┐
│     VALID       │ ─────────────────────────> │     EXPIRING_SOON      │
│  (Normal Op)    │                            │  (Console alerts shown)│
└─────────────────┘                            └────────────────────────┘
                                                           │
                                                           │ Expiration date reached
                                                           ▼
┌─────────────────┐       After 14 days        ┌────────────────────────┐
│     EXPIRED     │ <───────────────────────── │      GRACE_PERIOD      │
│ (Console locked │                            │  (14-day Read-Only)    │
│  to admin/lic)  │                            │ (Firewall runs cached) │
└─────────────────┘                            └────────────────────────┘

Lifecycle States​

StateConditionImpact on In-Process AI Firewall (agent/)Impact on Control Plane Console (server/)
VALIDvalidUntil > now() + 30 daysFull protection. Real-time dynamic rule polling.All modules enabled. CAB sign-offs active.
EXPIRING_SOONnow() < validUntil <= 30 daysFull protection. Real-time dynamic rule polling.Yellow banner warning with days remaining.
GRACE_PERIODExpired, but <= 14 days elapsedZero disruption. Agents continue enforcing the last cached ruleset via AtomicReference.Read-Only Mode. CAB approvals and rule publishing frozen. Prominent renewal banner.
EXPIREDExpired > 14 daysFallback to local default policy (PERMISSIVE_WITH_LOG or strict local static rules).Console locked. Requires license renewal to restore management access.

Quota Enforcement (maxMonitoredServices)​

  • The license defines the maximum number of AI microservices and LLM endpoints allowed to register simultaneously.
  • If the quota is reached (e.g. 25/25 services), existing services continue to operate and report metrics normally.
  • New services attempting to register receive an HTTP 402 Payment Required / Quota Exceeded response until the license is upgraded or inactive services are decommissioned.

6. SuperAdmin Operations: Issued Licenses Registry​

For platform operators and administrators running PrismScale, the Platform Operations Portal provides a centralized Issued Licenses Registry (Registru Licențe Emise):

Key Operational Capabilities​

  1. Target Selection: Toggle between On-Premise (Air-Gapped) and Cloud SaaS Tenant.
  2. Auto-Slug Generation: For On-Premise customers, leave the ID Client field blank; the engine automatically constructs an audit-friendly slug based on the customer name (e.g. spitalul-judetean-4a8f9c12).
  3. Expiration Tracking & Days Remaining:
    • Real-time countdown badges: VALID (365 zile rămase), EXPIRĂ ÎN 14 ZILE, EXPIRAT.
    • Filters by deployment type (All, On-Premise, SaaS Cloud) and status.
  4. Instant Re-Download (.lic): If a client misplaces their license file, administrators can re-download the exact signed .lic envelope with one click directly from the registry table.
  5. Zero-Downtime License Rotation: Updating a license does not require database downtime. Once the new .lic file or secret is replaced, the backend detects the new envelope and updates in-memory entitlement immediately.

7. Verification & Troubleshooting​

Check License Status via CLI​

# Check container logs for verification message
docker logs prismscale-backend | grep -i "License Check Result"

# Example output on success:
# INFO 1 --- [main] i.p.licensing.RsaLicenseService : PrismScale RSA-4096 Master Public Key loaded successfully.
# INFO 1 --- [main] i.p.licensing.RsaLicenseService : PrismScale License Check Result: status=VALID, valid=true, message=License active for Banca Comercială Meridian S.A.. Valid for 365 days.

Inspect Health Endpoint​

curl -s http://localhost:8080/actuator/health | jq .

Common Issues & Remediation​

Error MessageCauseRemediation
INVALID_SIGNATURE: RSA verification failedThe .lic file was modified, truncated, or corrupted during transfer.Re-download the unmodified prismscale.lic from the SuperAdmin registry and re-mount.
NO_LICENSE_FOUNDNeither PRISMSCALE_LICENSE_FILE nor PRISMSCALE_LICENSE_KEY was found.Check volume mount path and ensure file permissions allow read access by user app (UID 1000).
LICENSE_EXPIREDThe validity date has passed and the 14-day grace period has elapsed.Obtain a renewed prismscale.lic from PrismScale Operations and replace the existing file.
QUOTA_EXCEEDEDNumber of monitored microservices exceeds maxMonitoredServices.Request a license quota upgrade or archive unused AI models in the inventory table.

8. Summary Checklist for DevOps Teams​

  • Copy prismscale.lic to the host VM or create the Kubernetes Secret.
  • Configure PRISMSCALE_LICENSE_FILE pointing to the mount location.
  • Confirm backend logs show PrismScale License Check Result: status=VALID.
  • Verify web console shows the enterprise customer name and valid module badges in the header.
