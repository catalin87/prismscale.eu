Quickstart

Run a protected AI conversation in Java.

Use the Spring Boot reference application to see a protected model request, a tool proposal and the decision your application makes before an action can take effect.

Start with a working flow

Run the reference tests using synthetic data. The fixture does not require a live model key.

See the boundaries you own

Your application supplies identity and owns authorization, approvals and business transactions.

Verify before connecting a live model

Check the exact SDK, Java version, framework and provider profile you plan to install.

Source-based walkthrough · local provider fixture

Prepare the local environment

You need the PrismScale source tree, Java 17 or 21 and the repository Maven wrappers. Run the commands from the root of that source tree. Maven needs access to dependencies on the first build.

1. Install the local SDK modules

This puts the SDK artifacts in your local Maven repository so the reference application can resolve them.

(cd agent && ./mvnw -B -DskipTests install)
(cd agent/spring-prism-pro && ./mvnw -B -DskipTests install)

2. Verify the Spring Boot example

The reference suite uses local fixtures for model responses and synthetic business data.

(cd examples/boot-protected-conversation && ./mvnw -B verify)

3. Inspect the results

What a successful run demonstrates

Protected request
Only the representation permitted by the configured policy reaches the model fixture.
Tool proposal and approval
The host checks the resource. A pending approval produces no business effect until the authorized user confirms.
Uncertain execution
The application reconciles state before repeating an action that may already have taken effect.

Connect the reference flow to your application

  1. Configure a supported provider profile

    Confirm the compatibility evidence for the exact version you are integrating. Keep provider credentials on the application side.

  2. Supply authenticated HostContext

    Use tenant, principal and conversation from your application session. Register tools with bounded arguments and explicit resource authorization.

  3. Verify effects and output

    Check request minimization, rejection and approval against your application state. Protect output for the authorized recipient and keep raw payloads out of logs.
