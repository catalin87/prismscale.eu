Explore the three components

Java application

Where protection and authorization happen

The SDK inspects supported requests and tool flows in the same Java process. The host supplies the signed-in identity and checks access to the actual resource. It owns the transaction and its outcome.

Model provider

What the model can see and propose

Your configured provider receives content allowed by local policy. A model response can propose a tool call. The host evaluates the proposal before any action changes an application record.

Control Plane

Where teams manage policy and governance

The Control Plane manages policies and governance records and can receive permitted operational metadata. Prompts and model responses use a separate application-to-provider path.

Plan the deployment

Hosting
Evaluate hosted and self-hosted Control Plane options separately from the deployment of the Java workload.
Responsibility
The host owns identity, access checks, business transactions, retries and the effect of tool calls.
Availability
Validate outage and restart behavior using the exact SDK version and the configuration you intend to deploy.

Integration and operational checks

  1. Wire the model boundary

    Select a supported Java provider profile and configure the request path through the protected client. Verify the final provider-bound shape against synthetic fixtures.

  2. Bind actions to the host

    Pass authenticated host context, authorize the resource, and implement confirmation and idempotency in the application.

  3. Verify the runtime behavior

    Inspect model-bound data, permitted telemetry, and the actual effect of allowed and denied requests. Exercise provider failures and restart behavior in your deployment.
