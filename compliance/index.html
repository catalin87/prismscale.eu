What reviewers can verify

Recorded assessment
Read the submitted answers, associated outcome and available assessment history in the system dossier.
Human decision
Where CAB review applies, the decision is attributed to the authenticated reviewer. If the assessment changed before the decision, the console can require a refresh.
Current configuration
Current CAB policy can be consulted alongside the review. It is presented as current configuration because there is no per-decision policy snapshot.

What the technical file contains

Source
The file is generated from the system and the assessment and runtime configuration available at generation time. Regenerating it can reflect newer information.
Formats
Review the HTML view, download Markdown or export a PDF. The recorded decision actor and configured document signatories have different roles.
Review and access
Authorized readers can inspect the material. Responsible reviewers check applicability, completeness and sign-off before relying on it.

What is recorded and what your team verifies

What can I inspect after submitting an assessment?

The dossier presents recorded answers, the classification, the applicable criteria reported by the evaluator and its rationale. For a high-risk result routed to CAB, the assessment and the human decision are separate records.

What can the technical file populate?

The generator pulls fields already available in PrismScale, including the system name and intended purpose, risk classification and rationale, configured runtime rules and recorded approval data when available.

Which parts need review before export?

Review generated sections and template text against the actual system. Add or verify supporting material such as testing, monitoring and human oversight evidence where applicable. The organization owns the final documentation.
